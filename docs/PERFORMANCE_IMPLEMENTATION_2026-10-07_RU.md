## Что реализовано

| Область | Изменение |
|---|---|
| Неактивные холсты | Через 1,5 секунды оригиналы из full-size cache и больших image data URL в значениях нод записываются в долговременный архив. В состоянии остаются ссылки. Одинаковые изображения внутри архива дедуплицируются. Перед открытием холста оригиналы восстанавливаются. |
| Безопасность выгрузки | Состояние очищается только после успешной записи. Проверка идентичности не позволяет медленной записи затереть фоновые результаты. При восстановлении сохраняются новые cache slots, изменения промптов и порядок карточек; удалённые ноды не восстанавливаются. Холсты с detached windows не выгружаются. |
| Изображения вне видимости | OptimizedThumbnail и VisibleImage удаляют src у невидимого элемента с небольшим запасом 120 px. Это позволяет браузеру освобождать декодированные изображения. Реальное время освобождения RAM/GPU определяет браузер. |
| Превью | Общая очередь с параллелизмом 2, отменой ожидающих задач и освобождением ресурсов. Для data URL используется отдельный Worker с OffscreenCanvas; при недоступности — ограниченный canvas-путь. Асинхронный WebP сохраняет прозрачность. Исходник не появляется в DOM до готовности miniature. |
| Кэш превью | LRU с бюджетом 12 MiB по консервативной оценке размера строк. SHA-256 полного источника и размера исключает прежние совпадения коротких ключей. Незавершённые запросы объединяются, последний уходящий потребитель отменяет обработку. Хэширование тоже проходит через ограниченную очередь. |
| MultiView | Обе колонки виртуализированы; источники читаются по одному, preview импорта ограничен 256 px. Текст перед размонтированием сохраняется, сфокусированная строка остаётся смонтированной. Задачи генерации живут независимо от компонента и обновляют исходный холст по ID карточки. |
| Image Sequencer | Список промптов виртуализирован с измерением высоты строк и поддержкой перехода к кадру. В галерее outputs используются ленивые miniature, крупные preview выгружаются вне видимости. |
| Batch Prepare / Image Input | Крупные панели и нарезки используют VisibleImage; существующие miniature получают общий ограниченный декодер. |
| ZIP результатов Image Input | После сохранения ZIP и списка файлов в IndexedDB React хранит metadata и archiveKey. Просмотр/скачивание загружают данные по запросу. ZIP не удерживается внутри DOM/state постоянно. Замена результата и размонтирование удаляют временные записи; при отказе записи исходный результат остаётся в памяти для восстановления. |
| Batch Manager | Cached jobs стартуют с metadata. Изображения, raw JSONL и входные изображения читаются только для просмотра, вставки, скачивания или повтора. Закрытие карточки освобождает её загруженный payload. Web cleanup читает отдельную таблицу metadata; native cleanup не удерживает payload всех архивов одновременно. |
| История | Оригиналы перенесены в долговременный архив; React хранит миниатюры и ссылки. Чтение истории идёт через индекс timestamp с лимитом, а не getAll. Старые записи мигрируют без удаления оригиналов при ошибке хранения. Просмотр и экспорт получают оригинал по запросу. |
| React / граф | NodeView и OutputPanel подписываются на выбранные поля Context. Upstream cache инвалидируется для изменённых нод и их потомков; неизменные значения не разбираются повторно ради сигнатуры. Повторная запись идентичного full-size изображения не обновляет весь cache. |
| Сессия | Записи сериализованы, timestamps возрастают, выбирается самый свежий корректный snapshot. Ошибки записи на диск сообщаются; recovery-копия всё равно сохраняется. Исправлены старые неработающие импорты дублирующего media hook. |

## Контракт оригиналов

- Worker и canvas-encoder создают **только UI-превью**. Они не заменяют источник серверного запроса.
- MultiView хранит точный originalImage и долговременную копию. Активный граф сохраняет inline originalImage для существующих синхронных downstream-читателей; cooling неактивного холста выгружает и эти строки.
- Image-port и данные промптов MultiView отдают оригинальные байты, UI-путь — thumbnail. Собственный серверный запрос MultiView читает долговременный оригинал.
- Отсутствие оригинала не вызывает автоматической отправки thumbnail: запрос завершается ошибкой. Для старых MultiView-карточек без подтверждённого оригинала требуется повторный импорт.
- AI Editor не отправляет локальные A/B preview при отсутствии их оригинала в full-size cache.
- Переносимый экспорт холста/проекта материализует original bytes из архивов. Экспорт не зависит от cache другой машины. Отсутствующий архив останавливает экспорт с ошибкой.
- Новые originalArchiveKey и canvasOriginalArchiveKey защищены обходом ссылок при очистке кэша.

## Что ещё требует отдельного этапа

1. Единая async asset-модель для **активного** графа. Сейчас синхронные связи, copy/undo, detached windows и обработчики используют data URL; активные оригиналы остаются доступны в RAM. Без миграции всех этих читателей немедленная выгрузка оригиналов скрытых активных нод нарушит обработку. Декодированные DOM-превью уже управляются по видимости.
2. Streaming ZIP и отдельные asset-файлы вместо больших JSON-архивов. При первоначальной упаковке, открытии архива или portable export полное содержимое временно загружается. Модальное окно файлов читает архив целиком, хотя miniature декодируются лениво.
3. Полное разделение AppContext на доменные stores и мемоизация остальных тяжёлых потребителей. Выборочные подписки добавлены в два основных потребителя, архитектура остальных сохранена.
4. Сбор runtime-метрик на реальных 30 изображениях 2K/4K: pan/zoom, смена холстов, сворачивание, MultiView textarea, открытие/закрытие архива, background generation. Проверить отсутствие повторяющихся long tasks >50 ms и плато памяти после нескольких циклов. Не следует считать сборку доказательством достигнутых 60 FPS.
5. Разделение большого JS bundle на лениво загружаемые редакторы/provider modules. Это влияет прежде всего на старт приложения; уменьшение decoded image memory решается описанными механизмами.

При отказе хранилища приложение намеренно удерживает оригинал в памяти. Это безопасное ухудшение производительности вместо потери данных.
