# Диагностика Tripo 3D — 2 октября 2026

## Причина ошибок из приложенных логов

В интеграции смешивались два несовместимых контракта API:

1. Изображение загружалось в `https://openapi.tripo3d.ai/v3/files` и возвращало `file_…`.
2. Этот токен передавался в старый `https://api.tripo3d.ai/v2/openapi/task` с полями `file/files`, `type`, `model_version`.
3. После ошибки `2003: The image file is empty` обработчик повторял запрос на другом адресе.
4. Последний адрес `/v3/task` не существует, поэтому пользователь видел `4001: No endpoint found`, а первоначальная ошибка терялась.

Смешивание контрактов подтверждается кодом и логами. Несовместимость ссылки на загруженный файл — вероятное объяснение `2003`; без исходных изображений и проверки на сервере нельзя исключить повреждение самих файлов. Успешная загрузка показывает, что ключ был принят для этой операции. В логах нет отказа авторизации или сообщения о недостатке кредитов; проверить настройки аккаунта по этим логам полностью нельзя.

## Исправления

| Обнаруженная неисправность | Изменение |
| --- | --- |
| Загрузка v3, генерация v2, несуществующий `/v3/task` | Новые генерации используют только v3: `/files`, `/generation/image-to-model`, `/generation/multiview-to-model`, `/tasks/{id}`. Payload использует `input/inputs` и `model`. |
| FRONT/BACK передавались как два соседних элемента без обозначения сторон | В `inputs` каждый ракурс имеет свой ключ: `front`, `left`, `back`, `right`. Проверяется обязательный front; единственный front идёт в image-to-model. |
| Любая ошибка запускала перебор адресов | Ошибки API сохраняются с кодом и рекомендацией сервера. POST после потери ответа не повторяется автоматически, чтобы не создавать дубликаты платных задач. |
| Прокси Vite вызывался в статической сборке и Electron `file://` | Прокси используется только в dev. Production обращается непосредственно к v3. Dev fallback разрешён для явно отсутствующего маршрута, а не произвольного отказа POST. |
| `model_url`, `rendered_image_url`, `error_message` не читались при polling | Результат и причина отказа читаются в формате v3; сохранена поддержка старых полей. Успех без ссылки на модель считается ошибкой и содержит Task ID. |
| Обновления прогресса затирали Task ID устаревшим состоянием | Асинхронные обновления объединяются с актуальным состоянием ноды. ID локальной очереди хранится отдельно от ID Tripo. |
| Отмена не доходила до upload/create/status fetch | Сигнал отмены проходит по всей цепочке. Сигналы очереди и ноды объединены. Подписки на abort очищаются после ожидания. Отмена обозначается `cancelled`, а не `failed`. |
| Запрос мог зависнуть, единичный сбой polling обрывал ожидание | Таймаут отдельного запроса — 60 секунд; polling учитывает общий срок. Временные сетевые ошибки, 429, 5xx и код 2000 повторяются ограниченно только для чтения статуса. |
| Base64 ошибочно считался токеном; MIME/расширение могли расходиться | Распознаются токены и base64, проверяются пустые файлы, сигнатуры PNG/JPEG/WebP и размер 20 MB. MIME и расширение согласуются с байтами. Это проверка формата, а не полный декодер изображения. |
| По умолчанию 2M faces без Ultra; Auto в UI отображался как 2M | По умолчанию Auto. Старые несовместимые лимиты переводятся в Auto. Список ограничен моделью и Quad, параметры проверяются до загрузки. Смена модели сбрасывает плотность и Quad. |
| `texture=false` мог сопровождаться `pbr=true`, что включает текстуры на сервере | При отключении текстур выключается PBR; payload согласован. |
| Quad-результат FBX сохранялся как `.glb` и передавался GLB-просмотрщику | Расширение скачивания берётся из URL. Для FBX/OBJ/STL показано пояснение о необходимости внешнего 3D-редактора. |
| Retexture использовал старый endpoint и payload | `/models/texture` с `input` и `texture_prompt`. |
| Batch query ожидал массив вместо карты задач | Обрабатывается карта `data.tasks`, запросы делятся на группы до 100 ID, отсутствующие ID запрашиваются отдельно. ISO даты переводятся в миллисекунды. |

Для восстановления старых задач разрешён только **GET** в v2 после ответа «не найдено» из v3. Новые загрузки и генерации между версиями не переключаются.

## Проверка и ограничения

- `node --test scripts/tripo-service.test.mjs`: 22 проверки реального сервиса с подменой fetch; реальные кредиты и ключи не используются.
- `npm run build`: production-сборка проходит. Vite сообщает о большом размере основного JS bundle.
- `npm run lint`: остаются существовавшие до изменений ошибки в `hooks/components/nodes/media-viewer/useMediaState.ts` (неверные импорты и связанные implicit-any). Новых ошибок в изменённых файлах нет.
- Реальная генерация, баланс аккаунта, CORS в установленной сборке и доступность конкретных моделей не проверены запросами к аккаунту Tripo.
- Отмена прекращает локальную отправку/ожидание; если сервер уже создал задачу, она может продолжить работу и расходовать кредиты. Её Task ID сохраняется для восстановления.
- Скачивание по внешнему URL зависит от браузера: атрибут `download` может не задавать имя для другого origin. Уведомление теперь сообщает о начале скачивания, а не о гарантированном сохранении.
- API image/multiview generation использует визуальный вход. Текстовое поле ноды сохраняется как описание в истории; в неподдерживаемое поле `prompt` оно больше не отправляется. Текстовая инструкция для retexture передаётся в `texture_prompt.text`.

## Как проверить после обновления

Перезапустить dev-сервер или пересобрать Electron-приложение. Включить Tripo и оставить текущий ключ, выбрать H3.1, плотность Auto, Quad выключен. Сначала проверить одну картинку, затем FRONT + BACK. В логах должны быть только `/v3/files`, `/v3/generation/…` и `/v3/tasks/…` для новой генерации.

Рекомендуемое разрешение входных изображений — от 256×256. Размеры 3–4 KB в логах сами по себе не доказывают повреждение или слишком низкое разрешение. Если после исправления остаётся `2003`, потребуется проверить исходное изображение; сообщение сервера теперь не будет заменяться ошибкой другого endpoint.
